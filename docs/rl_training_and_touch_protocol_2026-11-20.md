# AS2-W + R1-A7 + O6：分阶段强化学习与目标触碰实验协议

> 更新日期：2026-11-20  
> 性质：**研究设计与复现实验约定**。本文件不代表阶段训练代码、奖励函数、球体接触判定或评测脚本已在本仓库实现，也不代表已经完成新的仿真实验。

## 1. 研究目标、平台和基础条件

- 统一研究对象为 **AS2-W 四轮足底盘 + R1-A7 上身双臂 + O6 灵巧手**；关注整机协调的**强化学习控制算法**，不将底盘与双臂作为两个独立机器人。
- 第一轮移动操作任务是**目标触碰**，不是抓取、搬运或物体姿态控制。目标为固定在支架上的刚性球体。
- 使用既有稳定站立/零命令控制作为进入训练的基础。此前 W4 的训练表现由用户判断满足该基础要求；**W4 的完整代码尚未合入此 GitHub 仓库**。
- 保留仓库已有的 MuJoCo/WBC v6 和 **100 Hz、21 工况**历史基准，不用新实验覆盖旧评分协议；Isaac Lab/RSL-RL 的训练与 MuJoCo/WBC 历史基准须分别标明环境与协议。
- 借鉴 RoboDuet 的**两阶段 RL 训练组织**，但训练模型、奖励和对照仍需按本机器人动力学和实验任务独立验证。

## 2. 训练阶段

### 阶段 1：双臂固定，训练轮足底盘

- 保持双臂在选定固定姿态，仅学习轮腿与轮子的底盘控制。
- 任务覆盖启停、转向、原地调姿及滚动中调姿，重点观察稳定、跟踪、制动、支撑和滑移。
- 记录：速度与姿态跟踪误差、停车距离/漂移、轮端滑移、稳定时间、四轮支撑和最小轮载。
- 当前状态：**协议确定；不能依据此文档认定本仓库包含相应训练入口或已复现实验**。

### 阶段 2：准备与联合训练

先验证球体、两侧拇指指腹碰撞体、有效接触区、可达性诊断和成功判定，再开展**选定侧手臂 + 轮足底盘**的联合强化学习训练；未选定侧手臂不得通过偶然触球满足目标。

#### 2.1 准备：球与手的冻结版本

- 第一轮使用仿真器真实几何值（球心、球半径、两侧拇指指腹有效区标定中心），统一转换到**世界坐标系**。
- 冻结机器人/手部模型版本、指腹有效区定义、球体几何来源、接触判定版本、容差 `epsilon` 和试次清单版本。
- 球位至少按**高度、距离、方位角**组织；具体数值、范围和训练/测试划分在正式配置表中另行冻结，不能在本文件臆定。

#### 2.2 准备：左右手选择（已确认规则）

1. 完成每个回合的复位与沉降后，**在首条运动指令发出前的同一物理时刻**读取左右拇指指腹有效区的标定中心 `p_L`、`p_R` 与实际球心 `c`。
2. 两个中心均位于球外时，计算两侧到球表面的距离：`d_L = ||p_L - c|| - r`、`d_R = ||p_R - c|| - r`，其中 `r` 为球半径。
3. 若 `|d_L - d_R| > epsilon`，选择距离球表面**较近**的一侧；若差值落在容差内，按**预先均衡分配的试次清单**决定侧别，不在运行中随机决定。
4. 侧别一经选定即锁定至回合结束，不得按运动中的可达性、距离或策略表现重新选侧。
5. 同一个正中球位允许安排两个试次、左右手各一次。**试次编号是复现主键**：训练、回放和算法对照须复用同一编号对应的初始配置与侧别。
6. `epsilon` 用**同一初态反复复位、沉降后**的 `d_L-d_R` 波动来标定，在正式试次前冻结，同时记录版本、量纲和标定数据。不能根据测试表现事后调参。
7. 即使被指定为较近侧但该侧难以触及，该试次仍保留在完整评测分母；不得临时切到另一侧或剔除困难样本。

> 如果任一中心不在球外、测量非有限值或几何信息无效，应先记录准备阶段的几何/数据异常；上述球外距离公式不应未经核验直接套用。异常处理动作与终端规则须在代码实现前明确冻结。

#### 2.3 准备：触碰与失败诊断

- **有效目标**：被锁定一侧的 **O6 拇指指腹有效碰撞区域**首先与目标球表面发生合格接触，而非指尖边缘、拇指侧面、掌面或其他手指擦碰。
- 使用法向接触力持续时间或冲量等**去抖规则**以排除瞬时数值碰撞；阈值与持续时间须标定，不在此文档捏造数值。
- 明确区分：有效首次触碰、其他身体部位先碰、非选定侧手先碰、支架碰撞、跌倒、超时、接触数据缺失。数据缺失不等价于“无接触”。
- 将**首次触碰成功**与**触后稳定成功**分为两个独立可报告指标；不得以触后稳态掩盖先碰错误。
- 可达性诊断至少区分：**预检查无可行 IK**、训练/执行中受**关节极限**约束、受**支架干涉**阻挡，以及其他执行失败；预检查不可达不能直接被解释成策略失败。
- 在预设校准试次中验证分类符合预期后才冻结接触判定；校准失败时先修复模型和分类器，不将异常试次直接计入正式对照。

## 3. 第一轮目标触碰的动作能力对照

在**相同机器人模型、球/支架几何、试次编号、初始姿态与沉降、超时时间、接触判定以及评价口径**下，只改变可使用的动作能力：

| 组别 | 可使用的动作 | 比较目的 |
| --- | --- | --- |
| A | 仅伸展选定侧手臂（底盘固定） | 单臂可达性基线 |
| B | 车轮滚动 + 选定侧手臂 | 检验移动扩大触碰能力的贡献 |
| C | 轮腿调姿 + 车轮滚动 + 选定侧手臂 | 检验轮腿姿态协同的增益及代价 |

这三组是**动作能力消融对照**，不应与**控制算法基线**混淆。IK/QP、统一 PPO、分阶段 PPO、奖励融合等可作为待研究的算法比较候选，**算法列表尚未最终冻结，也不能在未经实现和复现实验时称其结果**。

## 4. 报告要求和可复现数据

- 核心指标：合格首次触碰成功率、触后稳定成功率；按球位高度/距离/方位角、选中侧别、可达性类别分层统计。
- 代价与缺点同样报告：到达时间、轮子运动距离、腿部姿态调整量、能量/动作幅度（若模型与日志支持）、碰撞/跌倒/滑移。
- 每条正式试次至少存：`trial_id`、场景/模型/策略/协议版本、球心与半径、左右标定中心、`d_L`/`d_R`、`epsilon` 与选择理由、锁定侧别、初始状态、随机种子、完成/失败/异常标签、首次接触事件及触后稳态。
- 同一 `trial_id` 对所有算法、A/B/C 对照保持初始配置一致；保留所有正式试次，包括失败和较近侧不可达的困难试次，禁止因结果不佳更换分母。
- 未知或未冻结参数（如球半径、超时、力去抖阈值、IK 容差、动作上下限、奖励权重）必须以“**待冻结**”标记，不以推测数值代替实验设定。

## 5. 仓库代码状态和下一步实现边界

截至本协议创建，本仓库 `main` 的主工作代码仍为 **MuJoCo/WBC v6**；该文件只更新**设计记录**，**没有同步 W4 的 Isaac Lab 训练代码，也没有实现阶段 2 接触 RL 环境**。需要从完整的 W4 训练工程进行源文件级迁移与审查，单独保留训练入口、仿真模型、奖励、观测、随机种子、实验配置和版本锁定，而不要覆盖 WBC 旧工作或混淆两个仿真后端。

后续实施和验证顺序建议为：核验 W4/Isaac Lab 源代码与环境版本 → 固定阶段 1 训练/回放入口 → 实现阶段 2 的几何与接触校准 → 冻结试次清单和容差 → 接入联合 RL 训练及 A/B/C 消融 → 在统一试次表上对比算法并报告优势与劣势。
