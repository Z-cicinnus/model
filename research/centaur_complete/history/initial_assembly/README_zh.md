# 四轮足半人马

本模型将 AS2-W 四轮足底盘与 R1-A7 上部机构组装成一棵运动学树，在同一个 MuJoCo 系统中计算质量、惯量、关节运动和执行器反作用。主模型名称为“四轮足半人马”。该版本用于后续整机控制开发，目前完成模型组装及基础验证，未验证整机移动或转向稳定性。

## 模型组成

| 项目 | 数值 |
| --- | --- |
| AS2-W 来源 | 最新提供的 AS2W(1).xml；36 个网格来自先前 AS2W_control_project.zip 的 original/meshes |
| R1-A7 来源 | 上一步生成的 r1_a7.xml，源数据为本次提供的 URDF 和 19 个 STL |
| AS2-W 质量 | 26.00000000 kg |
| R1-A7 质量 | 16.19940901 kg |
| 合计质量 | 42.19940901 kg，未增加安装件质量 |
| 有质量刚体 | 37 个，不含 world |
| 主模型基座 | 1 个 freejoint，在 AS2-W 根部 |
| 活动关节 | 33 个：底盘腿关节 12、轮关节 4、上部机构 17 |
| 执行器 | 33 个理想关节输出力矩 motor，gear=1 |
| nq / nv / nu | 40 / 39 / 33 |
| 网格 | 55 个：AS2-W 36，R1-A7 19 |

上部 `r1a7_pelvis_link` 直接作为 `as2w_base_link` 的子刚体，安装处不增加自由度，也不通过两个独立仿真实例交换信息。腰部偏航自由度保留；手臂、头部的源关节链保留。各连杆质量、局部质心与惯量均与输入模型一致，没有另外加入汇总惯量或重复质量。

所有底盘名称加 `as2w_`，上部沿用 `r1a7_`。主模型使用 `inertiafromgeom=false`、`fusestatic=false`；相机等固定子刚体单独保留。AS2-W STL 仍按源模型乘 0.001，R1-A7 STL 为米制、不缩放，两部分不会混用单位。

## 装配位置

以 AS2-W 的 base_link 为参考，采用源模型的 +X 前方、+Y 左方、+Z 上方方向。R1-A7 pelvis 原点暂定在 [0.120, 0.000, 0.165] m，安装四元数 wxyz=[1,0,0,0]，即位于底盘前部中线、与底盘朝向相同。该位置是依据网格外形选取的仿真装配初值，不是安装孔位标定值；当前基座碰撞凸包与 pelvis 凸包间距约 6.4 mm，连接由刚体树固定关系实现。没有虚构连接板的实体质量或惯量。

安装位置与初始腿部姿态集中在 `assembly_config.json`。确定真实接口尺寸和连接板数据后，应更新该配置并添加真实安装件的质量与惯量，然后重新生成与校验。

在 home 姿态下，整机质心相对底盘原点为约 [0.0646374, -0.0001744, 0.0560785] m。此值会随腿部、腰部和双臂姿态变化，不能当成所有姿态共用的固定重心。

## 文件与使用

| 文件 | 作用 |
| --- | --- |
| centaur.xml | 正式浮动基座整机模型，后续控制算法入口 |
| fixed_base.xml | 同一机构的固定基座检查版本，用于查看装配和上部动作 |
| meshes/as2w、meshes/r1a7 | 完整 55 个源网格 |
| source/ | 两个输入 XML 和 R1-A7 原始 URDF，保留输入参数供复核 |
| assembly_config.json | 安装位姿、home 姿态、步长等设置 |
| actuator_map.json | 33 个执行器顺序、名称、关节与力矩范围 |
| validation.json | 编译、参数、动力学与耦合检查结果 |
| inventory.json | 交付文件清单和 SHA-256 |
| Assembly_Preview.png | MuJoCo 实际渲染双视图 |
| scripts/ | 生成、校验、查看、渲染脚本 |

解压后，进入 centaur_quadruped 目录：

```bash
python -m pip install -r requirements.txt
python scripts/view_model.py
python scripts/validate_model.py
```

默认查看器使用固定基座，避免装配查看时因缺少整机支撑控制而倒下。查看器仅含演示用重力补偿和关节保持；`--floating` 可以启动浮动版本，但不代表已有经过验证的站立或移动控制器。

控制开发时应加载主模型并显式恢复 home：

```python
from pathlib import Path
import mujoco

root = Path('centaur_quadruped').resolve()
model = mujoco.MjModel.from_xml_path(str(root / 'centaur.xml'))
data = mujoco.MjData(model)
mujoco.mj_resetDataKeyframe(model, data, model.key('home').id)
mujoco.mj_forward(model, data)
```

home 的各腿关节角为 [0,0.65,-1.30] rad，车轮角为 0.65 rad，基座高度为 0.424039531 m。源文件的膝关节零位在其范围之外，因此不要直接把全零关节状态当成站立初值。home 是合法装配姿态，不是已求得的接触静力平衡解，开始时轮地约有毫米级间隙。

XML 通过相对路径引用 STL，下载后需保持整个目录结构。单独的 XML 不包含网格字节。source 下的 XML 为输入存档，直接加载时其原相对路径未必有效；正式使用根目录的主模型。

## 执行器与观测

全体 `data.ctrl` 均为关节输出端 N·m。AS2-W 原来的 position/velocity 伺服被统一替换成 gear=1 的 motor，力矩限值保留：髋和大腿 ±60 N·m，膝关节 ±90 N·m，轮关节 ±15 N·m。R1-A7 的每个电机限值沿用源 URDF；名称和范围见 actuator_map.json。这些范围不等于经过实机验证的持续输出能力。

原 AS2-W 控制程序使用 gear=20 的位置接口和 gear=10 的速度接口，其 ctrl 适配公式不能原样用于当前模型。后续控制器应直接写入期望关节力矩，按名称查询执行器，避免沿用旧索引。此处没有添加未知的电机转子惯量、减速器动态或物理阻尼。

提供理想仿真关节位置、关节速度、执行器力矩和机身 IMU 信号。四元数为世界坐标下机身姿态；陀螺仪与加速度计使用 centaur_imu 局部轴，加速度计为 MuJoCo 定义的比力信号，不能直接当成世界坐标线加速度。未添加传感器噪声、延迟、滤波或状态估计器。

## 已完成的验证

MuJoCo 3.17.0 编译通过，主模型只有一个浮动根关节，R1-A7 pelvis 的父刚体确为 AS2-W base。逐刚体检查质量、局部质心和重建惯量矩阵，与两个输入模型的最大差均为 0；总质量严格等于两部分之和。home 中所有有限位关节均处于范围内，质量矩阵正定，33 个电机的指令与实际广义驱动力一致。

整机质量矩阵中底盘与上部关节的耦合块非零；另在无重力、无接触条件下，使用 RK4 给左肩施加 1 N·m 内力矩并积分 0.02 s，底盘产生可测的反向响应，总线动量与角动量残差分别约为 1.6×10⁻¹² 和 3.9×10⁻¹³。这一测试验证两部分的物理耦合，使用 RK4 是为了降低守恒量检查中的离散积分误差；正式模型默认使用 implicitfast、1 ms 步长。

固定基座版本完成 1 s 重力补偿保持，关节漂移为 0。主模型完成 0.1 s 地面接触动态运行，无非有限数或引擎警告。这是装配与基础动力学检查，不是整机站立、移动或转向控制验证，也不覆盖所有姿态。

## 当前边界

碰撞几何沿用源网格，MuJoCo 以凸包处理；为建立统一模型基线，机器人内部自碰撞暂时关闭。所有机器人碰撞 geom 的掩码为 contype=1/conaffinity=2，环境为 2/1；视觉 geom 不参与碰撞。不能用此版本宣称已排除手臂、底盘或腿部之间的运动干涉。后续需要独立建立自碰撞几何和排除对。

地面统一为 z=0，摩擦系数设为 0.8（扭转 0.002、滚动 0.0001），去掉源文件中的空气密度和粘度效应。上述为明确的仿真环境设置，不改变刚体惯性参数。

R1-A7 相机连杆源惯量明显偏小，当前保留原值等待 CAD/厂家数据复核。关节速度上限不会由 motor 自动强制执行；R1-A7 源速度上限仍保存在关节 user[0] 中。源 AS2-W XML 没有显式速度上限，不能将其 user=0 解读为允许速度为零。

后续步骤为核定真实安装接口及安装件数据，完成整机碰撞几何，再以这一统一动力学模型开发重力补偿、支撑力分配及移动转向控制。原底盘曾验证的移动效果不能直接视为本次增加上部机构后的验证结果。
