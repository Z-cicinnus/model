# 第4项：统一整机移动操作基准 v1.0

此版本固定模型、场景、任务、目标生成方式、输入输出和评价协议。包含双腕末端运动与底盘移动的组合目标，不包含物体抓取/释放、夹爪或负载搬运。建立环境不等于现有控制器已完成所有任务。

## 运行与算法接入

`python benchmark/validate.py` 检查接口。
`python benchmark/run.py --task all` 运行现有原地位姿保持控制器的基线；可单选 tasks.json 中任务。基线控制器不读取任务目标，故仅用作“保持站立、不执行操作”的负对照，不作为新的移动操作算法。任务不通过会如实记录success=false，程序不会因此停止其余任务。

`from benchmark.env import CentaurEnv`；构造 `env=CentaurEnv('straight_reach')`；`obs,info=env.reset(seed=42)`；循环调用 `obs,reward,terminated,truncated,info=env.step(action)`。终止或截断后必须reset。末次info含metrics。该类提供相似的五元组接口，但不是Gymnasium子类；PPO训练框架需要薄包装及对应spaces。MPC可使用env.m获取同一模型，但不得直接改env.d状态或对基座施加虚拟支撑。

动作：33维实际电机输出力矩，单位N·m，顺序为模型执行器顺序；按源XML限幅，非法形状与NaN拒绝。物理及力矩更新步长均1ms。所有算法对比使用相同1kHz执行接口；较慢策略必须明确其动作保持/插值或低层控制器，不能隐含改变执行频率。早期50Hz力矩保持试运行导致原站立PD失稳，正式协议已固定1kHz。未声称1kHz优化器实时可实现；此处为仿真时间协议。

观测：101维float64，依次qpos40、qvel39、归一化时间1、目标基座位置3、目标基座四元数4、目标左右腕位置6、目标左右腕四元数8。位置与目标姿态为世界系，四元数wxyz；qvel沿MuJoCo定义。无传感器噪声、延迟或状态估计；所有算法均获得同样真值。不能将此结果外推为实机。

## 固定任务和轨迹

总时长12s，0–2s保持，2–8s采用五次平滑阶跃到目标，8–12s保持末态。与whole_body_ik往返轨迹不同，本基准不自动导入旧往返参考。

- hold：保持初始基座和双腕位姿。
- dual_reach：双腕前移15mm并上移15mm，基座保持。
- posture_reach：上述双腕目标，加机身俯仰1°。
- straight_reach：底盘前进0.2m，同时双腕相对初始基座布局前移/上移15mm。
- turn_reach：基座偏航15°，双腕目标位置和朝向随偏航旋转，并叠加上述位移。
- disturbed_reach：双腕任务，第6–6.2s施加世界X方向30N扰动。

基座姿态用SciPy外禀'zy'顺序生成；本套任务无同时非零偏航/俯仰。双腕保持初始朝向，转向任务的腕部朝向随偏航旋转。末端取腕yaw连杆原点，非夹爪TCP。轮地软接触、自碰撞、统一惯量与原装配位置不变。默认确定性，无随机化；seed42用于标识与未来扩展，当前改变seed不会改变任务。

## 指标和成功判据

统一记录基座位置、左右腕位置、基座与腕部SO(3)角度误差的RMSE和终值；绝对关节机械功积分sum(abs(tau*qdot))*dt、力矩限幅次数、最大力矩占比、内部碰撞步数、累积奖励。机械功不是电池能耗。内部碰撞指两非世界刚体间超过1µm的穿透；每物理步检查。

判据固定于tasks.json：基座位置RMSE<30mm，双腕各RMSE<12mm，基座角度RMSE<0.5°，腕部各角度RMSE<5°；最终基座位置<20mm、双腕各<12mm、基座角度<0.5°；完整运行且无内部碰撞。跌倒（横滚/俯仰超过20°或高度低于0.25m）、非有限状态或引擎警告提前终止，计失败。

奖励为负归一化误差平方之和与小力矩惩罚的时间积分，公式见env.py；奖励与成功判据分开，不允许各算法自行更换评价公式后直接比较。基准版本、模型和任务文件SHA-256随结果保存。修改模型、轨迹、阈值、步长或观测后须升级基准版本并重跑全部算法。

输出results/pose_hold_baseline：每任务JSON与100Hz降采样轨迹NPZ，指标和奖励基于完整1kHz数据；summary.json汇总。不把负对照的成功率称作全身QP成功率，QP尚未接入本基准。results/interface_validation.json记录确定性回放、非法动作与限幅检查。

后续顺序：为同一接口接入面向任务的控制器并完成移动/转向，再比较MPC、PPO、增强RL和融合算法。抓取搬运需加入夹爪/物体/质量/接触定义，建立v2并保留v1结果；当前没有虚构抓取成功率。
