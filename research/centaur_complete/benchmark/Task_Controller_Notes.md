# 统一任务跟踪控制器

此控制器接入既有benchmark-v1.0六任务；不改tasks.json、模型参数、地面摩擦或成功标准。统一整机39维速度QP负责双腕、基座和轮腿参考，33个电机驱动浮动基座模型。没有改写实际基座状态或添加虚拟支撑。

## 结构

参考规划50Hz，电机控制1kHz。QP仍采用SciPy SLSQP求解凸二次目标与线性约束。双腕位置缩放20、姿态3；基座位置/姿态40；姿态正则为关节0.1、基座0.01、轮轴0.001。目标速度来自误差×5，全部使用当前任务目标函数，而非旧的往返轨迹。QP参考是离线生成，不能称为在线全身QP或MPC。

每轮接触位置取轮体原点竖直下方0.086m，用其材料点雅可比形成瞬时纵向滚动与法向约束。法向包含轮心高度误差恢复；侧向速度为软惩罚（缩放0.5），允许四轮差速转向时侧滑。此为平地低速近似，不含摩擦锥、接触力优化或轮胎变形；偏航运动最终由原模型软接触仿真检验。未加入碰撞距离不等式，所有参考采样仍做内部碰撞检测，碰撞或负支撑载荷会拒绝执行。

准静态前馈根据各参考姿态的重力偏置与四轮竖直载荷求解，随后以PD跟踪33关节参考。四轮关闭角位置PD，采用轮速误差阻尼和基座纵向/偏航反馈；左右轮使用反向偏航力矩。纵向控制含目标速度前馈与积分；偏航含目标角速度前馈与积分，均设分量限幅，最终由环境执行器限幅。

在50Hz实际状态反馈中，将基座横向/高度与横滚/俯仰误差映射为四腿参考修正：delta_q_leg = -3.0 pinv(J_contact_leg) J_contact_base delta_base，每关节修正裁剪至±0.12rad，并将最终关节位置目标裁剪至源模型限位内。纵向位移和偏航由轮控制处理。这是约束雅可比的局部反馈，不是在线力矩QP；该修正可减小转向侧滑造成的机身误差，但不能外推为全局稳定保证。双腕暂无独立的在线末端误差闭环，主要跟踪全身QP关节参考。

## 运行和查看

在centaur_quadruped目录运行 `python benchmark/run_tasks.py --task all`；单项可选hold、dual_reach、posture_reach、straight_reach、turn_reach、disturbed_reach。命令打印全部原始指标，results/task_qp_v1下保存JSON和NPZ。参考在仿真执行前求解，可能需要等待；尚未测量实机实时计算能力。

`python benchmark/replay_tasks.py --task straight_reach` 或 `--task turn_reach` 可在MuJoCo窗口回放已保存状态。回放不是另一轮动力学验证。NPZ中的qpos/action/samples为100Hz日志，reference_qpos/reference_qvel为50Hz参考，reference_dt给出步长；samples字段沿用env.rows，依次时间、基座位置误差、左/右腕位置误差、基座角度误差、左/右腕角度误差、奖励。评价指标基于全1kHz序列。

旧pose_hold_baseline仍保留为保持控制负对照。development/initial_controller保存初次任务控制器及其测试结果，其中转向未通过；该快照仅用于开发追踪，不是推荐运行入口。正式对比应使用results/task_qp_v1对应的最终代码。使用同一任务集调参后的结果属于开发集表现，未来需另设未参与调参的测试轨迹评价泛化。
